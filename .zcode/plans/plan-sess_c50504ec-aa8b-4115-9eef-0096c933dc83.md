# Plan: Fitur Smart Receipt & Nota Parser Menggunakan DeepSeek API (Server-Isolated Engine)

- Tanggal: 2026-08-28
- Status: draft

## Tujuan
Memudahkan pencatatan pengeluaran/pemasukan dari struk belanja, nota, bukti transfer, atau SMS banking secara instan dengan engine AI DeepSeek (`deepseek-v4-flash`). Menjaga keamanan penuh agar API key DeepSeek tersimpan secara rahasia di environment server (`.env.local` / Next.js Server Route) dan tidak bocor ke client-bundle maupun git repository.

---

## 1. Analisis Keamanan & Isolasi API Key
- **Prinsip Zero-Leak Client**:
  - API Key `DEEPSEEK_API_KEY` dan model `DEEPSEEK_MODEL` ditaruh di `.env.local` (sudah terdaftar di `.gitignore`).
  - Tidak ada prefix `NEXT_PUBLIC_` sehingga Next.js compiler menjamin variabel tidak pernah diekspor ke browser / JS bundle.
  - Seluruh komunikasi dengan endpoint `https://api.deepseek.com/chat/completions` dilakukan di server Next.js App Router (`/api/ai/parse-receipt`), dilindungi oleh validasi sesi JWT `requireAuth(req)`.
  - Client hanya mengirimkan teks/payload struk beserta daftar kategori/dompet user yang sedang aktif ke backend aplikasi sendiri.

---

## 2. Ruang Lingkup Pekerjaan

### A. Konfigurasi Lingkungan & Variabel Server
- Update `.env.example` dengan template panduan konfigurasi:
  ```env
  DEEPSEEK_API_KEY="sk-..."
  DEEPSEEK_BASE_URL="https://api.deepseek.com"
  DEEPSEEK_MODEL="deepseek-v4-flash"
  ```
- Set nilai konfigurasi aktif di `.env.local` menggunakan API key dan model yang diberikan.

### B. Validasi Schema & Service Helper (`src/lib/validations.ts` & `src/lib/deepseek.ts`)
- Schema Zod `parseReceiptRequestSchema`:
  - `text`: string teks struk / OCR / SMS / catatan belanja (wajib, max 4000 karakter).
  - `categories`: array `{ id: string, name: string, type: 'expense' | 'income' }`.
  - `wallets`: array `{ id: string, name: string, type: string }`.
- Output parser schema `parsedReceiptResultSchema`:
  - `amount`: number (nominal transaksi).
  - `type`: 'expense' | 'income' | 'transfer'.
  - `date`: string YYYY-MM-DD (tanggal transaksi dari struk).
  - `description`: string (nama toko / rincian ringkas).
  - `suggested_category_id`: string uuid / null.
  - `suggested_wallet_id`: string uuid / null.
  - `items`: array `{ name: string, price: number }` (opsional untuk rincian belanja).
- Modul server `src/lib/deepseek.ts`:
  - Fungsi `parseReceiptWithDeepSeek(payload)` yang memanggil endpoint chat completion DeepSeek dengan prompt terstruktur & format JSON response.

### C. Server API Endpoint (`src/app/api/ai/parse-receipt/route.ts`)
- Handler `POST`:
  1. Verifikasi autentikasi sesi JWT `requireAuth(req)`.
  2. Rate limiting / validasi input body dengan Zod.
  3. Memanggil DeepSeek AI dengan timeout guard 15 detik.
  4. Mengembalikan hasil parsed JSON yang siap dipakai form.

### D. Integrasi UI / UX di Frontend
1. **Modal / Panel Scan Struk (`src/components/transactions/ReceiptParserModal.tsx` atau tombol Scan di `TransactionModal.tsx`)**:
   - Tombol "Scan / Parse Struk" dengan ikon kontekstual Receipt / Sparkle di bagian header `TransactionModal` dan tombol shortcut di `QuickActions`.
   - Area input cepat:
     - Tempel teks / SMS banking / mutasi / nota struk.
     - Pratinjau hasil parsing (Total belanja, Toko, Tanggal, Kategori tebakan, Rincian item).
2. **Auto-Populate Transaksi**:
   - Sekali klik "Terapkan ke Transaksi", seluruh field di `TransactionModal` otomatis terisi (`amount`, `type`, `date`, `description`, `categoryId`, `walletId`).
   - Pengguna tetap memegang kendali penuh untuk meninjau/mengubah sebelum menekan "Simpan".

### E. Pengujian & Verifikasi (Audit & E2E)
- Tambahkan unit test di `scripts/audit-self-test.ts` untuk memverifikasi validasi schema parser dan handling fallback bila input struk tidak lengkap.
- Tambahkan integrasi test di `scripts/e2e-full-suite.ts` untuk memverifikasi endpoint `/api/ai/parse-receipt` (dengan mock / sandbox response) serta isolasi autentikasi.
- Jalankan `npm run lint`, `npm test`, dan `npm run build` untuk memastikan 100% lulus.
